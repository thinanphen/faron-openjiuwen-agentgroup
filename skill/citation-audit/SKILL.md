# 法条引用自检（citation-audit）

> **一句话**：判定一段法律文本里的法条引用是否真实存在、是否落在本案由的请求权基础范围内。
> 判定**不调用任何大模型**，是纯确定性规则，因此结论可复现、可用反例现场验证。

---

## 这个 Skill 解决什么问题

通用 Agent 会说「我查过了」。在法律、医疗、金融这类高风险域，
**「模型自称查过」不是证据**。

本 Skill 把「引用是否成立」变成**代码级规则判定**：

```
正文文本
  ↓ extract_citation_tokens()   确定性正则（中日文条号 / 日文分条 / 美国法典 §NN）
token 去重
  ↓ article_covers()            归一化后：完全相等，或落在合法条号边界的前缀
【第一段】能否在「本次工具真实返回」中找到 → 未覆盖项点名
  ↓ same_law()                  名称互含即同法（含中英别名）
【第二段】是否落在案由图谱的请求权基础范围内 → 超范围项列出
```

**关键性质**：不调用模型 / 确定性 / 可反例验证 / **零三方依赖**（只用 Python 标准库）。

---

## 何时使用

| 适用 | 不适用 |
|---|---|
| 需要校验 AI 生成的法律文书里的法条引用 | 需要检索法条（那是 `laws_search` 类工具的职责） |
| 需要给「引用是否可靠」一个可审计的结论 | 需要判断法律结论对错（本 Skill 只判引用，不判实体） |
| 需要在没有模型 Key 的环境里跑可信校验 | 需要中文全量法库（本 Skill 只校验，不提供语料） |

**触发词**：法条引用校验 / 引用自检 / 幻觉条号 / citation audit / 条文号核对

---

## 参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `body` | string | ✅ | 待校验正文（起草稿全文） |
| `returned_refs` | array | ✅ | **本次工具真实返回**的法条列表，元素形如 `{"title": "民法", "article_no": "第五百二十二条"}`。这是第一段的唯一判据 |
| `law_names` | string[] | ❌ | 案由图谱的请求权基础法名（**匹配用**，可含中英别名）。给了才做第二段 |
| `law_names_display` | string[] | ❌ | 展示用主名；缺省沿用 `law_names` |

> ⚠️ `returned_refs` 必须是**工具真实返回**的集合，不能是模型自述引用过的条文。
> 这是「自检」与「自查」的分界：前者读登记簿，后者读模型的话。

## 返回

```json
{
  "total": 2,
  "covered": 1,
  "ok": false,
  "unmatched": ["第9999条"],
  "report_markdown": "- 识别到条文号引用 2 处（去重）\n- …",
  "applicability": {
    "checked": 3,
    "in_scope": ["民法"],
    "out_of_scope": []
  }
}
```

`ok=false` + `unmatched` 非空 = 有引用未获凭证，**应人工核实或删除后再采用**。

## 用法

### 作为 CLI（零依赖，评委可直接试）

```bash
python scripts/audit_citations.py --demo
```

输出会展示一个**故意埋雷**的例子：正文引用 `第9999条`（库里不存在），被当场点名。

### 用自己的文本

```bash
python scripts/audit_citations.py \
  --body-file draft.md \
  --refs-file returned_refs.json \
  --law-names 民法 会社法 \
  --json
```

### 作为 Python 模块

```python
import sys; sys.path.insert(0, "scripts")
from audit_citations import audit

r = audit(
    body="依据第五百二十二条与第9999条，本案应支持原告请求。",
    returned_refs=[{"title": "民法", "article_no": "第五百二十二条"}],
)
print(r["unmatched"])   # → ['第9999条']
```

## 支持的引用形式

| 形式 | 示例 | 判定 | 说明 |
|---|---|---|---|
| 中文 / 日文条号 | `第百三条` `第五百二十二条` | ✅ | 主场景 |
| 日文分条 | `第百三条の二` | ✅ | 也接受 `之` / `ノ` |
| 美国法典 | `§1125` `§1125(a)` `§102-1` | ✅ | **含字母款项** |
| 条文更完整 | 工具返 `第一百四十三条第二款`，正文写 `第一百四十三条` | ✅ 命中 | 正当前缀 |
| 款项前缀 | 工具返 `§1125(a)`，正文写 `§1125` | ✅ 命中 | 正当前缀 |
| **少写一位** | 工具返 `§1125`，正文写 `§112` | ❌ **不命中** | 假条号必须拦住 |
| **半截括号** | `§1125(` | ❌ 不命中 | 不构成完整引用 |
| 不同款项 | 正文写 `§1125(b)`，工具只返 `§1125(a)` | ❌ 不命中 | 款项可区分 |

## 已知边界（如实声明）

1. **只判引用，不判实体**。条号真实且适用 ≠ 法律结论正确。
2. **判据依赖 `returned_refs` 的完整性**。如果调用方漏传工具真实返回的法条，
   会把真引用误判为「未覆盖」。工具侧的登记必须发生在**结果截断之后**。
3. **法名匹配用「互含」**，不是严格同一性。中英法名不一致时需要 `law_names` 提供别名，
   否则会产生「超范围」误报。
4. **不校验条号格式的立法正确性**。例如 `第9999条` 会被正确地判为「无凭证」，
   但本 Skill 不去判断它「是否超出该法的条文总数」——那需要法库元数据。
5. `§` 前缀的正则要求 `§` 与数字之间可有空白，但不接受全角 `§`。

## 来源与对齐

本 Skill 的规则与 **法元（Faron）桌面端 TypeScript 实现**逐条对齐，
避免双端行为漂移：

| 本 Skill | 上游对应 |
|---|---|
| `extract_citation_tokens()` | `src/lib/agent.ts` · `extractCitationTokens()` |
| `article_covers()` | `agent.ts` · `articleCovers()` |
| `same_law()` | `agent.ts` · `sameLaw()` |
| 两段自检编排 | `agent.ts` · 质检步骤 |

**两处对上游的修订**（已回写建议）：

- **G11**：上游引用正则为 `\(\d+\)`，只支持数字款项 `(1)`；
  实测 `'Under §1125(a)'` 抽取结果为 `'§1125'`，**`(a)` 被丢弃**，
  导致 `§1125(a)` 与 `§1125(b)` 被当成同一处引用。本 Skill 改为 `\([0-9a-zA-Z]+\)`。
- **G12**：上游图谱法条节点缺 `name_alt`，中英法名不一致时
  `sameLaw` 互含判定失败，产生「超范围」误报。本 Skill 支持传入别名。

**另修一处自身缺陷（E9）**：上游 `articleCovers` 是裸前缀比较，
`"§1125".startswith("§112")` 为真 → 少写一位的假条号能蒙混过关。
本 Skill 要求 token 必须是**被条号正则认可的完整单元**。
