## 关于持续集成（CI）：**本项目未启用 CI**

**如实说明**：本仓库**没有** `.github/workflows/`，**未启用任何 CI 服务**。

**原因**：启用 GitHub Actions 需要一个带 `workflow` 作用域的 Personal Access Token；
当前两台开发机上的 PAT **均缺少该作用域**，推送 workflow 文件会被 GitHub 拒绝
（`refusing to allow a Personal Access Token to create or update workflow`）。
为不引入一个"看起来配了其实从没跑过"的假 CI，**选择不配**。

**替代方案（已落地且可现场验证）**——本地一键验证，效果等同 CI 的"每次提交前全绿"：

```bash
./verify.ps1        # Windows
./verify.sh         # Linux / macOS
```

内部调用 `tools/run_all_checks.py`（10 步，含**工作区干净闸门**）；
**退出码 0 = 全绿，非 0 = 并指出是哪一项**。
干净克隆上实测 **9/9 通过、exit 0**，重复运行工作区仍保持干净。

> 换句话说：**CI 该做的事我们在本地做了，只是没接 GitHub Actions。**
> 这是能力选择，不是遗漏。
