### EV7 单测：41 组，并抓出两处真实缺陷

`npm test` → **41 passed (41)**；`npm run build` → **exit=0，79 modules**。

单测**实际发现**（非猜测，由断言触发）`src/lib/evolution.ts` 的 `jsonBytes` 两处缺陷：

| 缺陷 | 现象 | 修法 |
|---|---|---|
| 循环引用抛异常 | `JSON.stringify` 遇环直接抛 TypeError；该函数用于计算进化包体积 `size_bytes`，上游对象一旦有环就崩 | try/catch 返回 0 |
| 非 BMP 字符字节数低估 | 原实现把一切非 ASCII 按 3 字节算，漏掉 4 字节的补充平面字符（emoji 等） | 按 UTF-8 真实宽度 1/2/3/4 分档 |

同时**读出三处真实语义**（与我最初猜测不同，已按实际对齐）：
1. `applyDpNoise(counts: Record<string,number>, …)` —— 输入是**计数字典**不是向量
2. `evaluateAdoption` 采纳条件 = `无任何指标显著回归 AND 同向改善指标数 >= 2`
   —— **同理只改一项不足以采纳**（重要防误采纳设计）
3. 回归阈值是**乘性**的：`b < a*(1-tolerance)`

### EV2 配方消费：进化闭环最后一环接上

审计说这是「**最关键的一步**」。做法分两层，严格分开：

**① 纯函数派生层**（新增 `src/lib/recipe.ts`，198 行）
`deriveParams(recipe)` 把 `RecipeManifest` 折算成 6 个运行时参数。
`BASELINE_PARAMS` **刻意等于改造前的硬编码值**（`toolRoundsLimit: 6` = 原
`const MAX_ROUNDS = 6`），保证「没采纳过配方」的用户行为完全不变。

**② 真实接线到 `agent.ts`（4 个消费点）**

| # | 消费点 | 改动 |
|---|---|---|
| ① | `runAgenticToolStep` 轮数上限 | `const MAX_ROUNDS = 6` → `= rp.toolRoundsLimit` |
| ② | `runAgenticToolStep` 检索词 | 配方 `extraKeywords` 注入 system 提示 |
| ③ | 工具结果回填 | 新增 `limitToolText(res.text, rp.searchLimit)` |
| ④ | `planFromSkeleton` 弱化步骤 | `isDeprioritized()` 命中者移到末尾并标注可跳过 |

**关于 ③ 的一处刻意设计**：只截断**回填给模型的文本**，**绝不截断 `task.refs`**。
因为 `refs` 是「本次工具真实返回集合」、是引用自检的判据；为省上下文而砍掉它，
会让自检把真法条误判为「未覆盖」——那是把本产品最值钱的可信层弄坏。

**`RECIPE_CONSUMPTION` 事实清单**：逐字段声明是否真被读取，并写明 `where`。
`auditPassFloor` / `minSamples` 仍标 `wired: false`（已派生但无消费点），
由 `unconsumedFields()` 如实报出，并在 Evolution 页新增的可折叠明细表中展示。

**测试 33 组**（`tests/recipe.test.ts`），其中最关键的一组是
**「消费登记表 ↔ agent.ts 源码一致性」**：直接断言源码含
`MAX_ROUNDS = rp.toolRoundsLimit`、`limitToolText(res.text, rp.searchLimit)`、
`rp.extraKeywords`、`isDeprioritized(s.name, params)`。
**只改表不改代码、或只改代码不改表，这组测试都会红。**

## 环境级故障（影响「零成功记录」的归因）

```
本机 NO_PROXY = .ustc.edu.cn,localhost,127.0.0.1,::1,[::1]
```

`openai` 3.x 依赖的 `httpx2` 把 `NO_PROXY` 每一项当 URL 模式解析，
`[::1]`（带方括号 IPv6）解析出非法端口 → **构造客户端就崩**：

```
httpx2.InvalidURL: Invalid port: ':1]'
```

四组对照实验证实与 base_url 无关，**任何** OpenAI 兼容端点 6/6 全崩。
⇒ **在有这个 `NO_PROXY` 的机器上，配了真 Key 也发不出任何请求。**
修法：去掉 `NO_PROXY` 里的 `[::1]`（`run_stub_online.py` 已自动修正）。

另需 `pip install aiosqlite`（框架任务板必需，已进 `requirements.txt`）。
